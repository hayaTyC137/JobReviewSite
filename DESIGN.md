# Design System: Контур

Все значения живут в `src/index.css` как CSS-переменные `--c-*`. Компоненты не объявляют собственных цветов: только токены.

## Overview

**Creative North Star: «Реестр доверия»**

Контур — официальный, но современный инструмент: соединение делового реестра и аналитической панели. Интерфейс должен ощущаться спокойным, точным и прозрачным. Глубокий тёмно-синий задаёт вес, светлые холодные поверхности держат данные, стальной синий отмечает действия и проверенные факты.

**Key Characteristics:**

- глубокая сине-графитовая палитра с одним пастельным стальным акцентом, без кислотных и неоновых цветов;
- почти квадратные поверхности (0–2px), тонкие рамки, тень — только у плавающих элементов;
- Inter для текста и цифр, IBM Plex Mono для метаданных;
- движение плавное и объясняющее: появление данных, смена состояния, обратная связь.

## Colors

### Primary

- **Стальной сигнал** (`accent #6f93dd`): основные CTA на тёмном фоне, маркер активного, фокус-кольца. На нём всегда тёмный текст (`deep`), контраст 5.6:1.
- **Синий текст** (`accent-ink #2d4f93`): ссылки и акцентный текст на светлых поверхностях.

### Neutral

- **Глубокий синий** (`deep #0e1624`): header, hero, score-карточки.
- **Холст** (`canvas #eef1f5`): фон страниц.
- **Поверхность** (`surface-raised #ffffff`, `surface #f9fafc`): карточки, формы, отчёты.
- **Тональная заливка** (`surface-tint #e3e8ef`): переключатели, треки баров.
- **Текст** (`ink #131a26`), **вторичный** (`muted #5a6577`, контраст ≥ 4.5:1), **линии** (`line #d6dce5`).

### Status

`good #3f7a64`, `warn #9a6a24`, `bad #a2505a` — приглушённые и всегда вместе с иконкой и подписью («Высокая оценка», «Отзыв обжалуется»). Для категорий данных их не используют.

### Charts

`chart-1 #3a64b8` и `chart-2 #a8742c` прошли проверку валидатором палитры: различимы при дальтонизме (ΔE ≥ 20) и дают ≥ 3:1 на белом. Одна серия → только `chart-1`, легенда не нужна. Две серии → легенда + подпись значения у каждого столбика.

### Named Rules

**The Signal Rule.** Стальной синий появляется там, где нужно действие, подтверждение или изменение состояния. Большие заливки акцентом — только в одном месте на страницу (CTA-полоса каталога на главной).

## Typography

**Sans:** Inter Variable, с кириллицей. Plus Jakarta Sans и Outfit не подходят: у них нет базовой кириллицы.
**Mono:** IBM Plex Mono.

### Hierarchy

- **Display** (750, `clamp(34px, 5.2vw, 68px)`, tracking −0.03em): главный тезис страницы.
- **Headline** (750, `clamp(26px, 3.4vw, 39px)`): заголовки секций, заканчиваются точкой («Как менялись оценки.»).
- **Title** (650–700, 15–19px): названия компаний, карточек, графиков.
- **Metric** (700, 22–76px, tracking −0.03…−0.05em): оценки и score. Пропорциональные цифры для крупных чисел, `tabular-nums` — только в столбцах и на осях.
- **Body** (400–550, 13.5–15px, 1.5–1.6): описания и отзывы; мера 60–78 символов.
- **Label** (600, 10–11px, моноширинный, uppercase, tracking 0.04–0.1em): статусы, даты, подписи полей.

### Named Rules

**The Two Voices Rule.** Inter несёт чтение и цифры, Plex Mono — метаданные. Третьего шрифта нет.

## Layout

Максимальная ширина контента — 1280px, поля — `var(--gutter)` = `max(28px, (100vw − 1280px) / 2)`, на мобильных 16px. Каталог: sticky-панель фильтров 290px + лента карточек; до 900px фильтры уезжают в выезжающую панель. Профиль компании: шапка → сводка (score, критерии, реквизиты) → аналитика → отзывы.

Брейкпоинты: 1080, 980, 900, 820, 760, 680, 560, 420px. На ширине 320px страница не должна требовать горизонтального скролла.

## Elevation & Depth

По умолчанию — тонкие рамки и тональные поверхности. Тени:

- **Hover карточки компании:** `0 10px 28px rgba(19, 26, 38, .08)` + подъём на 2px.
- **Popover / dialog:** `0 16–24px 40–60px rgba(9, 15, 25, .16–.28)`.
- **Hero-report на главной:** жёсткая тень `16px 18px 0 #1b2840` — единственная «материальная» тень бренда.

## Shapes

0px для крупных поверхностей, 2px (`--radius`) для полей ввода. Круг — только для score-ring, live-точек и бегунков слайдеров. Бары графиков скругляются только на конце данных (4px), у основания — прямые.

## Components

### Buttons
- **Primary на тёмном:** фон `accent`, текст `deep`, высота 40–46px.
- **Primary в формах:** фон `deep`, текст `on-dark`.
- **Secondary:** белый фон, рамка `line`, при hover — `line-strong`.
- Все touch-цели ≥ 44px, фокус — `3px solid accent-ink`, offset 3px.

### Score Badge
Число + «/5» + текстовый уровень («Высокая / Средняя / Низкая оценка / Нет данных»). Цвет левой полосы дублирует уровень, но никогда не заменяет подпись.

### Verified Badge
Значок `BadgeCheck` + «VERIFIED CEO» или «VERIFIED OFFICIAL» на `accent-soft`. Показывается у подтверждённого представителя: в шапке профиля компании, в пометке об обжаловании, в карточке автора.

### Company Card (каталог)
Удлинённая горизонтальная карточка: глиф, название, локация, отрасль, описание (≤ 180 символов) | 6 мини-баров критериев | score badge + число отзывов. Внизу — полоса со свежим отзывом. Вся карточка кликабельна через растянутую ссылку на названии.

### Review Card
Автор (кнопка → карточка автора с рейтингом кандидатской активности), статус «работает сейчас / бывший сотрудник», должность, дата, оценка. Обжалуемый отзыв — янтарная полоса слева и пояснение с именем представителя.

### Inputs
Белое поле, рамка `line`; фокус — рамка `accent` + мягкое кольцо `rgba(111, 147, 221, .22)`. Ошибка — текст под полем, `role="alert"`, рамка `bad`.

## Motion

- Появление блоков: 0.3–0.5s, `cubic-bezier(.16, 1, .3, 1)`, смещение ≤ 14px, без bounce.
- Бары и линии графиков «дорисовываются» при попадании в экран (0.6–1.1s).
- Перестановка карточек при смене сортировки — `layout` без масштабирования.
- `MotionConfig reducedMotion="user"` + CSS `prefers-reduced-motion` отключают всё декоративное движение.
- Контент не должен зависеть от анимации: если IntersectionObserver не сработал, данные всё равно видны.

## Do's and Don'ts

### Do
- Показывать статус данных рядом с оценкой и честный empty state («Оценок пока нет»).
- Разрывать линию графика в месяцах без отзывов, а не рисовать ноль.
- Давать табличный вид для каждого графика.
- Проверять mobile, клавиатурный фокус и reduced motion.

### Don't
- Не использовать тёплые терракотовые/кофейные цвета из прежней версии системы.
- Не вводить новые hex-цвета в компонентах — только токены `--c-*`.
- Не использовать шрифты без кириллицы.
- Не делать pill-кнопки, градиентный текст и blur-карточки.
- Не оставлять декоративные подписи, похожие на неработающие вкладки.
