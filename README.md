# Контур — прозрачный реестр работодателей и сотрудников

**Контур** — платформа, где соискатели проверяют работодателей по честным отзывам, а работодатели — кандидатов по подтверждённой трудовой истории. Обе стороны видят одни и те же правила: рейтинг считается по открытой формуле, спорные записи разбирает модератор, а решения фиксируются.

**Ценность:**

- **Сотруднику** — отзывы нынешних и бывших сотрудников с оценками по 6 критериям, аналитика компании и собственная карточка сотрудника: стаж, официальные причины увольнений, оценки работодателей, которые можно оспорить.
- **Компании (директор / HR)** — проверенный профиль в реестре с логотипом и баннером, право обжаловать отзывы, ведение трудовой истории штата и оценка сотрудников.
- **Рынку** — защита от накруток: лимиты, запрет конфликта интересов, центр жалоб и публичный арбитраж.

Поддерживаются **Россия, Беларусь, Казахстан и Молдова** (Кишинёв, Бельцы, Тирасполь, Бендеры, Кагул, Унгены, Сороки, Оргеев, Комрат, Стрэшень, Хынчешть, Единец).

## Возможности по ролям

| Роль | Где работает | Что может |
|------|--------------|-----------|
| **Гость** | каталог, страницы компаний, «Связаться с нами» | искать компании (фильтры по стране, городу и 7 критериям), читать отзывы и аналитику, написать в поддержку |
| **Сотрудник** (`USER`) | `/me` — личный кабинет | писать отзывы; карточка сотрудника (итоговый рейтинг 0–100, метрики «Токсичность, Уравновешенность, Продуктивность, Командная работа, Надёжность, Коммуникация», трудовая история со стажем и причинами увольнений, история дисциплины); смена аватара и данных профиля; заявки на смену ФИО/имени/email через модератора; жалобы и обращения со статусами; регистрация своей компании |
| **Представитель компании** (`REPRESENTATIVE`: директор, HR) | `/company-panel` | профиль компании (логотип, баннер, описание, контакты), список официальных представителей и приглашение коллег, ведение штата: запись о приёме/увольнении с официальной причиной, оценка сотрудника по 6 метрикам, замечания (публикуются после модератора); обжалование отзывов о своей компании |
| **Модератор** (`MODERATOR`) | `/moderation` | мониторинг очередей и 7 очередей: новые компании, представители, изменения профилей, дисциплинарные записи, центр жалоб (арбитраж), обжалования отзывов, обращения в поддержку |
| **Администратор** (`ADMIN`) | `/admin` + всё, что у модератора | дашборд (пользователи, компании, отзывы, очереди, динамика за 12 месяцев, нагрузка API за час, JVM), управление ролями и блокировками, реестр отзывов (скрыть/вернуть), реестр компаний (опубликовать/приостановить), системные настройки |

**Интерфейс:** окно входа с асимметричными «живыми» радиусами, матовым стеклом, световым контуром и анимированным фоном; плавные переходы между страницами; на главной — живая статистика платформы, интерактивный симулятор прозрачного рейтинга и FAQ. Все анимации уважают системную настройку «уменьшить движение». Подробности — в [`DESIGN.md`](DESIGN.md).

### Бэкенд — модульный, по фичам (feature-based)

Каждый пакет владеет своими сущностями, репозиториями, сервисами, DTO и контроллерами; общие вещи вынесены в `common`, `security`, `config`.

```
com.jobreview
├── auth          регистрация, вход, дозаполнение профиля, привязка внешних аккаунтов (UserIdentity, OAuthAccountService)
├── user          пользователь, роли, публичная карточка автора, рейтинг кандидатской активности
├── profile       личный кабинет: смена данных, заявки на смену критичных полей
├── company       каталог, поиск (Specifications), аналитика, рейтинг, модерация реестра, CompanyAccess
├── companypanel  кабинет представителя: заявка в реестр, профиль, представители
├── employee      трудовая история, оценки работодателей, дисциплина, EmployeeScoreCalculator
├── review        отзывы и правила против накруток
├── appeal        обжалование отзывов представителями
├── complaint     центр жалоб: жалобы на отзывы, оценки, пользователей, компании
├── support       обращения «Связаться с нами»
├── moderation    сводка очередей и общий контроллер модерации
├── admin         дашборд, пользователи и роли, контент
├── analytics     публичная статистика, метрики нагрузки (RequestMetrics)
├── settings      системные настройки (закрытый список ключей с валидацией)
├── location      справочник стран и городов (включая Молдову)
├── files         безопасная загрузка изображений
├── security      JWT, фильтр аутентификации, OAuth 2.0 (регистрации провайдеров, обработчики входа)
├── seed          демо-данные и bootstrap первого администратора
└── common        ошибки (единый ApiError), rate limiter, общие DTO и шаблоны валидации
```

Слои внутри фичи: `Controller` (HTTP, OpenAPI, авторизация) → `Service` (бизнес-правила, транзакции) → `Repository` (Spring Data). Ошибки бизнес-правил — исключения (`NotFoundException`, `BusinessRuleException`, `AccessDeniedOperationException`, `InvalidInputException`, `TooManyRequestsException`), которые `GlobalExceptionHandler` превращает в JSON одного формата.

```bash

npm install
npm run dev                 # http://localhost:5173, /api и /oauth2 проксируются на :8080

npm run lint                # oxlint

# бэкенд
```

Основные переменные окружения бэкенда:

| Переменная | По умолчанию | Назначение |
|-----------|--------------|------------|

| `JWT_SECRET` | dev-значение | ключ подписи JWT, ≥ 32 символа — **обязательно сменить в проде** |

| `CORS_ORIGINS` | `http://localhost:5173,http://localhost:3000` | разрешённые origin |

## Вход через Google и соцсети (OAuth 2.0)

Поддерживаются **Google** и **LinkedIn** (OpenID Connect), **GitHub**, **Facebook**, **Яндекс ID** (OAuth 2.0). Каждый провайдер включается автоматически, если в окружении заданы **оба** его ключа; кнопки на фронтенде появляются только для включённых (`GET /api/auth/providers`). Профили Spring не нужны.

**Redirect URI** для консоли провайдера: `{адрес сайта}/login/oauth2/code/{провайдер}`

- Docker: `http://localhost:3000/login/oauth2/code/google`
- `npm run dev`: `http://localhost:5173/login/oauth2/code/google`

| Провайдер | Где создать приложение | Переменные | Что запрашиваем |
|-----------|------------------------|------------|-----------------|
| Google | Google Cloud Console → APIs & Services → Credentials → OAuth client ID (Web) | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | `openid profile email` |
| LinkedIn | linkedin.com/developers → продукт «Sign In with LinkedIn using OpenID Connect» | `LINKEDIN_CLIENT_ID`, `LINKEDIN_CLIENT_SECRET` | `openid profile email` |
| GitHub | Settings → Developer settings → OAuth Apps | `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | `read:user user:email` |
| Facebook | developers.facebook.com → приложение → Facebook Login | `FACEBOOK_CLIENT_ID`, `FACEBOOK_CLIENT_SECRET` | `public_profile email` |
| Яндекс ID | oauth.yandex.ru → создать приложение (веб-сервисы) | `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` | `login:email login:info` |

**Как это работает:**

1. Кнопка ведёт на `/oauth2/authorization/{провайдер}`; Spring Security перенаправляет к провайдеру с `state` (защита от CSRF).
2. После ответа провайдера `OAuthAccountService` ищет пользователя по паре *(провайдер, id у провайдера)*. Не нашёл — привязывает существующий аккаунт с тем же email, **только если провайдер подтвердил адрес**; иначе создаёт новый аккаунт с базовой ролью **«Сотрудник»** (`USER`).
3. Бэкенд выпускает собственный JWT и возвращает браузер на `/auth/callback#token=…` (фрагмент URL не уходит на сервер и в логи прокси). Новому пользователю добавляется `&onboarding=1`.
4. Страница `/welcome` запрашивает минимальные данные: публичное имя, страну и город, согласие с правилами — и email, если провайдер его не передал.

Ошибки (отмена у провайдера, блокировка, закрытая регистрация, провайдер без ключей) возвращают на `/auth/callback#error=…` с понятным сообщением.

## Ролевая модель (RBAC)

Права проверяются **трижды**: правилами URL в `SecurityConfig`, аннотациями `@PreAuthorize` на контроллерах и проверками владения в сервисах (например, «представитель именно этой компании»). Клиентские guards (`RequireRole`) — только удобство интерфейса.

**Роль и блокировка читаются из базы при каждом запросе** (JWT хранит только id пользователя). Поэтому смена роли администратором и блокировка действуют **мгновенно**, без повторного входа, а заблокированный пользователь теряет доступ со старым токеном.

| Действие | Гость | USER | REPRESENTATIVE | MODERATOR | ADMIN |
|----------|:-----:|:----:|:--------------:|:---------:|:-----:|
| Каталог, отзывы, аналитика, статистика | ✅ | ✅ | ✅ | ✅ | ✅ |
| Обращение в поддержку | ✅ | ✅ | ✅ | ✅ | ✅ |
| Написать отзыв | — | ✅ | ✅¹ | — | — |
| Жалоба на отзыв / оценку / пользователя | — | ✅ | ✅ | ✅ | ✅ |
| Своя карточка сотрудника, профиль | — | ✅ | ✅ | ✅ | ✅ |
| Карточка другого сотрудника | — | — | ✅² | ✅ | ✅ |
| Регистрация компании в реестре | — | ✅ | — | — | — |
| Профиль компании, представители, штат, оценки | — | — | ✅² | — | — |
| Обжаловать отзыв о своей компании | — | — | ✅² | — | — |
| Очереди модерации | — | — | — | ✅ | ✅ |
| Дашборд, роли, блокировки, контент, настройки | — | — | — | — | ✅ |

¹ кроме отзывов о собственной компании. ² только подтверждённый представитель опубликованной компании.

**Жизненные циклы:**

- **Компания:** `PENDING` (заявка, не видна в поиске) → `APPROVED` (опубликована, заявитель подтверждён) / `REJECTED` (с причиной; после правки снова `PENDING`) → `SUSPENDED` (решение администратора).
- **Критичные данные профиля** (публичное имя, ФИО, email): заявка `PENDING` → модератор `APPROVED` / `REJECTED`. Некритичные (аватар, должность, город, «о себе») меняются сразу.
- **Замечание работодателя:** `PENDING` (видно только сотруднику и модераторам, не влияет на рейтинг) → `CONFIRMED` / `REJECTED`.
- **Жалоба:** `OPEN` → `UPHELD` (отзыв/оценка скрываются, пользователю добавляется подтверждённая дисциплинарная запись) / `REJECTED`.

**Итоговый рейтинг сотрудника (0–100)** — формула показана в карточке: среднее шести метрик по каждой оценке (токсичность инвертируется: `6 − значение`) → среднее по оценкам → `(x − 1) / 4 × 100` → минус 5 баллов за каждое подтверждённое замечание (не больше 25).

## Меры предосторожности и безопасность

### Персональные данные

- **Минимизация.** Публично показывается только публичное имя («Анна К.»), должность и город. ФИО и email не публикуются, в публичных DTO их нет.
- **Карточка сотрудника не публична.** Оценки работодателей и дисциплина видны самому сотруднику, подтверждённым представителям компаний и модераторам; неподтверждённые замечания — только сотруднику и модераторам.
- **Критичные данные меняются через модератора** — нельзя сменить имя или email, чтобы выдать себя за другого сотрудника или уйти от истории.
- **Никаких внешних картинок.** Аватары, логотипы и баннеры принимаются только как файлы, загруженные на платформу; ссылки на сторонние серверы отклоняются валидацией — иначе чужой сервер видел бы IP и заголовки посетителей. Аватары соцсетей не сохраняются.
- **Загрузки безопасны:** тип определяется по сигнатуре файла (PNG/JPEG/WebP; SVG запрещён), имя генерирует сервер (UUID), чтение защищено от path traversal, лимит 2 МБ, `X-Content-Type-Options: nosniff`.
- **Пароли** хранятся только как BCrypt-хэши; у аккаунтов из соцсетей пароля нет.
- Страница «Связаться с нами» описывает запрос на выгрузку/удаление данных.

### Аутентификация и доступ

- JWT подписывается HS256 ключом из окружения (≥ 256 бит); права всегда берутся из БД, поэтому блокировка и смена роли вступают в силу немедленно.
- OAuth: проверка `state`, id_token (Google, LinkedIn) валидируется по JWKS и issuer; привязка к существующему аккаунту — только по email, подтверждённому провайдером; токен передаётся во фрагменте URL.
- Rate limiting (скользящее окно): вход — 10 попыток за 5 минут на аккаунт и 30 на IP; регистрация — 5 в час на IP; обращения — 5 в час; жалобы — 10 в час; загрузки — 30 в час.
- Заголовки: `X-Frame-Options: DENY`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` (бэкенд и nginx). CORS — только перечисленные origin.
- Администратор не может изменить собственную роль или заблокировать себя; нельзя понизить последнего администратора.

### Валидация отзывов

- Bean Validation на всех входящих DTO: длина текста 30–4000, оценки 1–5 по каждому критерию, обязательные поля; ошибки возвращаются по полям.
- Отзыв можно оставить только о **проверенной** компании.
- React экранирует весь пользовательский текст — HTML в отзывах не исполняется.
- Спорный отзыв не удаляется компанией: представитель подаёт обжалование, модератор принимает решение, пометка «на проверке» видна всем.

### Предотвращение накруток

| Мера | Где реализована |
|------|-----------------|
| Один отзыв об одной компании раз в 90 дней | `ReviewService.checkReviewAllowed` |
| Не больше N отзывов в сутки (настройка `reviews.daily_limit`, по умолчанию 3) | там же + админка |
| Запрет дословно повторяющихся отзывов одного автора | там же |
| Конфликт интересов: представители (даже неподтверждённые) не оценивают свою компанию, модераторы и администраторы не пишут отзывы | там же |
| Работодатель оценивает только тех, кто записан в его штат, и не может вести собственную историю | `EmployerService` |
| Компания публикуется только после проверки ИНН/IDNO модератором; дубликат ИНН отклоняется | `CompanyPanelService`, `CompanyModerationService` |
| Жалобы: одна открытая жалоба на объект от автора, нельзя жаловаться на себя | `ComplaintService` |
| Рейтинг компании пересчитывается сразу при скрытии отзыва | `CompanyRatingService` |
| Мониторинг «отзывов за 24 часа» и нагрузки API — сигнал для ручной проверки всплесков | `/moderation`, `/admin` |
| Поле-ловушка против ботов в форме обратной связи | `SupportService` |

## Известные ограничения и планы

- **Rate limiter и метрики нагрузки хранятся в памяти** одного экземпляра — для горизонтального масштабирования перенести в Redis / Micrometer + Prometheus.
- **Подтверждение email не реализовано**: адрес при регистрации и онбординге не верифицируется письмом. Следующий шаг — одноразовая ссылка через SMTP.
- **Загрузки лежат на диске** (том Docker `uploads`) — для нескольких экземпляров вынести в S3-совместимое хранилище.
- Помесячная аналитика админки группируется в Java по датам за год — на больших объёмах заменить агрегирующими SQL-запросами или материализованным представлением.
- В очереди жалоб превью цели загружается для каждой жалобы отдельно (очереди небольшие); при росте — пакетная загрузка.
- Кабинеты модератора, администратора и панель компании в демо-режиме без бэкенда показывают подсказку запустить `docker compose up`.
